Hybrid Noise/Wave Function Map Generator

Personal Project, 2025-2026
GitHub

A tile-based map generator that utilizes both simplex noise and wave function collapse methods of generation simultaneously. The map data structure is an Nth dimensional tree akin to an octree that stores tile superpositions (a tile can be multiple types simultaneously). Through a few passes of different generation methods, tile positions are given potential options, and then those options are refined down until only one remains.

The map above first generates a separate biome map, with each of the biome tiles containing generation information for that scaled portion of the terrain map. Noises are determined by the weighted average of all nearby biome noise calculations. Currently, the map is simply represented by cubes places at tile positions, but a mesh generation such as marching cubes could be used to reduce the number of polygons.

Wave function collapse generation is also supported for structures or other more rules-based generation, and can be done before or after the noise-based generation takes place.

Magia Nexus Stat System

Personal Project, 2025-2026
GitHub

A comprehensive and flexible stat system for use in games and beyond. Stats are modifiable containers that serve to either easily return a calculated value, or act as a data structure that stores values. Stats are bound to an object, so only a reference to the desired object is needed to access its stats. There are a few different root classes in the architecture:

  • Value Container: A stat that contains a value but does not accept modifiers. This is acts as a basic field.
  • Collection Container: A modifiable stat that does not have a value, but acts as a collection of values. They exist as the standard types of collections with modifier support (List, Queue, Dictionary, etc).
  • ImmutableContainer: An immutable value container that determines its value by some unique method.
  • Solver: A modifiable stat that contains an immutable value, calculated/solved by using its modifiers. This includes things such as numerical stats, priority orders, and damage calculations.
  • Modifier: A value container with game-relevant logic such as buff stacking and duration. These behaviors are controlled via the StatManager.

Magia Nexus Game Framework

Personal Project, 2024-2025
Project Page
GitHub

A flexible game framework intended for rapid prototyping and implementation. It supports easy additions of new mechanics and systems for any type of game. It is the subject of continual improvement as I use it for various projects and game jams. The framework is partially built off of the above stat system.

Its core components are:

  • Entities: Objects with default stat values and a dynamic list of mechanics.
  • Mechanics: Game functionality pertaining to the entity.
  • Stats/Modifiers: See above.
  • Triggers: Statically subscribeable and invokeable events that can accept events and “binding objects”. Instances can be made for use with the Task system, which is primarily useful within the Unity inspector.
  • Tasks: The intended recipient of a trigger invocation. They accept one parameter and perform one piece of functionality and return an boolean. When used alongside triggers and other classes that call them, they allow for rapid visual programming via the Unity inspector.

Simulation Modeling

UTD ATEC Capstone Project, Fall 2020
Project Page
GitHub
Download

A simulated volume using Position-Based Dynamics that can be interacted with in real time. It has a dynamically generated and updated mesh that can be exported to a .obj file. This was my senior capstone project at UTD. See the project page for in depth on my development process.

My implementation of Position-Based Dynamics (PBD) consists of 3 internal constraints, which each node in the simulation must attempt adhere to. They are compressive, stretch, and rotational constraints. Additionally there is an external static constraint that uses information from colliders to prevent the simulation from passing through them. The mesh is dynamically generated initially, then the vertices are updated in real-time as the nodes move around.

Reality Studio

Client Project at The Devhouse Agency, 2021
Project Page
GitHub

Reality Studio is a set of two applications and a Unity Editor tool developed solely by me. Its goal is to create an environment where interior design layouts can be quickly and easily created, changed, and viewed in a high fidelity AR experience by someone who is inexperienced with traditional 3d software.

The first application is called Content Creator, it is the 3d editor that allows the user to edit and manipulate an interior space. From there, a saved project can be uploaded to the second part of the pipeline. This is the Unity tool that uses AWS, Unity’s Lightbaking, and Unity Addressables to bundle the scene for mobile use. Once the project has been processed, it can be viewed within an AR environment on a phone or tablet.

Some of the more impressive systems I made found within the Content Creator app are:

  • Object and Surface Selection and Multi-Selection
  • Change History (Undo/Redo)
  • Mesh and Submesh Manipulation
  • Custom Project File Saving/Loading
  • Material and Preset Management

Additional information can be found on the project page. The linked Git repo will only contain individual systems out of context rather than the complete project. I would really recommend checking out the project page, there is too much to this project to put on this summary!

3D Game Framework

Created while at The Devhouse Agency, 2021-2022
Project Page
GitHub

While at The Devhouse Agency, I helped create many small 3d (and 2d) games, and for quite a few of them I was the primary systems developer. After a few projects of remaking the same basic systems again and again, I began creating all systems to be reusable, and over time it became a conglomeration of systems that I could import into projects to save days, sometimes weeks, of development time.

The systems I created as part of this framework include:

  • UI/Application States
  • Gameplay Objects
  • Player and AI Controllers
  • Character State Machine and States
  • Character Loadouts
  • Designer-Friendly Projectiles
  • Progress Saving
  • Audio Systems
  • Level Loading
  • Object Pooling
